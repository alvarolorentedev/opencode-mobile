# Design proposals

Proposals are exploratory designs that are not yet implementation contracts.
Each proposal states its status and links its mocks or evidence.

| Proposal | Status | Notes |
| --- | --- | --- |
| [Worktree UX](worktree-ux.md) | Proposal only — not implemented | Project/worktree selection, header breadcrumb, and New chat flow |

## Rules

- Keep the status near the top of the proposal and update it when the work
  ships or is abandoned.
- A proposal that changes the design system or an architectural boundary needs
  an [ADR](../../adr/README.md) once it is accepted.
- Implemented behavior belongs in the [design system](../design-system.md),
  [component inventory](../component-inventory.md), or
  [functional specification](../../product/functional-spec.md), not only in the
  proposal.
- Link mocks from the proposal and keep their relative paths stable.
